# Decisions

Owns: why the design is what it is, rejected options and when to revisit (D1–D24).
Not here: the rules themselves (`requirements.md`, `contracts.md`).
Update when: a request makes, changes or reverses a design decision; add or edit its row.

| ID | Decision | Because | Rejected | Revisit when |
| --- | --- | --- | --- | --- |
| D1 | Folder-registered plugin: MCP server, skill and hooks | The only official plugin contract; installs without touching Mixdog | Patching Mixdog's ASAR or provider loader; replacing built-in tools by name | Mixdog documents provider or tool-replacement APIs |
| D2 | Own Electron companion per MCP connection, launched by `bridge.exe` in a kill-on-close Job | Independent runtime, windows and profiles; no orphan processes | Mixdog's built-in browser or private bridge | — |
| D3 | Caller identity from single-use tickets issued by the PreToolUse hook | Model arguments cannot prove identity; hooks run in the host | Model-supplied session IDs | The host passes caller identity to MCP servers |
| D4 | Revocation terminates the companion | In-process removal of Chromium device grants cannot be confirmed; process exit can | Clearing internal caches | Electron offers confirmable grant revocation |
| D5 | JS dialogs through a wrapped `dialog.showMessageBox` paired with CDP events, pinned to Electron 44.9.1 | Electron has no documented dialog interception API | Patching page scripts | Any Electron upgrade |
| D6 | Shipped policy `delegated` for hid, usb, notifications, geolocation | Registering the package with this policy is the person's delegation; agents finish device flows on owned pages without routine handoff | Per-request human consent as the default (`manual` stays available) | The user wants per-request consent |
| D7 | One window per page: toolbar, live page view, transparent input shield | Normal browser UX; the person takes over the same live page | v0.1.0 split of a bitmap preview (automation) and a separate real window (human), with no address bar | — |
| D8 | No Mixdog side-panel embedding | Mixdog 1.3.5 plugins contribute only skills, MCP servers and hooks; the side-panel browser is Mixdog's own | Private bridge, core edits | Mixdog ships an official plugin panel or webview API |
| D9 | `CalculateNativeWinOcclusion` disabled and `presented()` bounded to 3 s | A window covered before its first frame never painted, so observe hung | Requiring a foreground window | Electron paints new occluded windows |
| D10 | File System Access pickers and `window.prompt` unsupported | Electron 44.9.1 throws on `prompt()`; FSA choosers would need a custom Electron/Chromium build (explored in a discarded prototype) | A custom Electron build | Electron exposes FSA chooser handling or supports `prompt()` |
| D11 | Agent DevTools as compact CDP reads on the page's own debugger session (`console`, `network`, `inspect`, `performance`), plus an explicit `evaluate` `world:'page'` opt-in and a handoff-only human DevTools window | Agents debug without driving the DevTools GUI by screen; observations cost 4k–28k tokens plus a PNG, so reads return text rows only, answer beside the action lane and paginate by cursor. Page-world reads use V8 `throwOnSideEffect` as a best-effort guard, not a security boundary. Page-defined functions, overridden built-ins and getters still run, so a read's result is reported by the page. Such reads are refused while the tab is paused (explicit Stop included). The page-world opt-in is needed for page globals; its risk is that page scripts can observe, spoof or tamper with the evaluation and its result, while it still has no Node or host authority. Recording only in `automation` keeps the person's handoff activity private. Service and shared workers serve the whole profile, so their records follow profile-wide privacy windows. Redaction is best effort by name and shape over headers, URLs, console text and request and response bodies; secrets under unrecognized names, markup content, binary bodies and page-world read results are not redacted (`contracts.md` DevTools reads) | Screen-driving Chrome DevTools; a second CDP client; recording during handoff; unbounded buffers; a pointer-per-owner unread mark (cursors are idempotent across retries and lost replies); full rows inside observations (results carry only error and failure counts since the last result, D13) | Observation format redesign; a need for request interception or emulation |
| D12 | Excluded from agent DevTools: `Debugger` domain (pause, breakpoints, stepping), Tracing and HeapProfiler, request interception or modification, emulation and throttling, cookie and storage CDP values | A paused page blocks every observation, input and return check, and enabling `Debugger` would make `debugger;` statements freeze pages; traces and heap snapshots are large and slow; interception and emulation change page behavior; cookie and storage values are account secrets beyond what isolated `evaluate` already reads from the DOM | Enabling them behind flags | A bounded, non-pausing design exists and the user asks |
| D13 | Page results are text: status line, signals, header, then a compact element projection (`role "name" states ="value"`) with `e<n>` refs; actions return a diff. Breaking change from v0.2.0: text results, `t<n>` tabs, `frame` (an iframe ref) instead of `frameId` | The old JSON observation cost 4k–28k tokens plus a PNG per step (naver main ≈27.7k estimated tokens → ≈2.2k; login ≈4.1k → ≈0.3k in a simulation from saved page samples). Diffs keep multi-step work cheap; JSON stays where agents parse fields (status, tabs, requests, permissions, downloads, DevTools reads) | Keeping JSON with fewer fields; an accessibility-tree dump; raw HTML; screenshots by default | Agents need structured fields from page results, or a tokenizer measurement contradicts the estimate |
| D14 | Refs are persistent connection-wide identities, retired only on node removal, rename, document replacement or `generation` change; never recycled or matched by role/name fallback | Refs that die on every observation forced re-observation after each step and produced false `uncertain`; a fallback could act on a different node with the same name | Per-snapshot refs; role/name re-resolution; selector refs | A site class defeats node identity (e.g. full re-render per keystroke) |
| D15 | One synchronous isolated-world walker snapshot per frame, captured in parallel; the snapshot carries its checkpoint; role, name and state helpers derived from Mixdog's `snapshot-scripts.ts` (`semantics.mjs`) without the `textContent` name fallback | All-frame revisions plus a global stamp made unrelated frames (tickers, ads) block input and cost ~108 serial CDP commands on a 13-frame page; `textContent` leaked CSS and script text into names | Per-frame CDP DOM walks; requiring all frames quiet | Sites need names the helpers cannot compute |
| D16 | Bounded settle after dispatch (150 ms probe, 3 s navigation, 100 ms quiet capped at 1 s / 500 ms short), structural mutations only, root and target frames only | Agents need the action's effect in its own result without waiting on unrelated churn; text tickers never settle | Fixed sleeps; network idle; all-frame quiet | Measured actions routinely miss their own effect |
| D17 | Disposition by evidence: before dispatch `not-executed`; during dispatch `uncertain`; acknowledged dispatch with failed observation `executed observed:false`; first input to a document waits out Chromium paint holding | An acknowledged dispatch happened; calling it `uncertain` invited replays. Chromium acknowledges and then drops input while a new document's commits are deferred, which would report an effect-less `executed` | Treating every post-dispatch failure as `uncertain`; retrying dropped input | Chromium exposes a delivery acknowledgement for dispatched input |
| D18 | Screenshots only on request at CSS scale; a point needs the latest screenshot-bearing snapshot, the same document, viewport and scroll, and an unchanged 24×24 CSS-pixel tile | Images cost more than the text view and were mostly unused; whole-image hashes failed on any animated pixel, while the tile proves what is under the point | Always attaching a PNG; whole-screenshot hashes; device-pixel coordinates | Agents need visual grounding by default |
| D19 | Agent windows open with `showInactive()`; an agent `handoff` only flashes the window; focus emulation on in `automation`, off in `native-handoff`, on the page and on every out-of-process iframe session; a person-initiated return (including closing human DevTools) may focus | A window that grabs focus could receive keystrokes the person meant for another app; focus emulation keeps pages behaving as focused without OS focus. Separate from the DevTools rule that recording never emulates (focus emulation is a presentation setting, not a recording side effect) | Focusing on every open or handoff; no emulation (pages blur and pause behaviors) | Sites misbehave under focus emulation |
| D20 | `run`: a plugin-owned script runner in a sandboxed, network-less hidden renderer whose only exit is a nonce-checked bridge; every op is one `browse` call through the same gates; `not-executed` steps throw catchable errors, `uncertain` seals the run | Multi-step forms cost one model round trip per step; a script does them in one call while each step keeps its validation, single dispatch and disposition. Nothing that was not sent can be resent, so a catchable not-executed error is safe and scripts commonly wrap optional elements; an unknown outcome must stop everything that follows, even inside a catch. A separate renderer with no Node and no network can be terminated mid-loop, and the main process re-checks every op. Not Mixdog's agent runner (C9) | Node `vm` (not a security boundary, shares the main process); running scripts in the page world (page scripts could tamper); `utilityProcess` (has Node); stopping on the first not-executed step (forces fragile scripts) | Scripts need ops outside the allowlist, or a run needs more than 100 s |
| D21 | Review hardening of perception and input: page-code refusal beside secrets (`SENSITIVE_PRESENT`), handoff-private signals and downloads, a dispatch guard in the target's walker world (`TARGET_MISMATCH`), owner stability across animation frames, a hit chain for points, an escape-path input guard, frame and item caps, words-only `find` | Security review findings (1 critical, 2 high, 6 medium, 4 low): a validated click could land elsewhere in a moving or covered cross-origin frame; page code could read a filled password; handoff activity reached signals; a regex could freeze the host. Refusing is simpler and safer than documenting the risk | Documenting `evaluate` beside secrets as a risk; running agent regexes in a worker with a timeout (more code, same outcome as words-only) | A site class needs page code beside filled secret fields |
| D22 | Runner review hardening: the bridge applies the host's `validateArgs` (invalid input is catchable, never uncertain); one shared runner partition behind a dead fixed proxy with WebRTC limited to proxied UDP and its constructors removed; a compile-only check in main (`node:vm`) before any sandbox; per-dispatch input credits instead of a 1 s grace; run-step native requests bound to the run's caller; `Page.press` removed (`Locator.press` stays); bounded final views and report | Runner security and functional reviews: untagged refusals sealed runs as uncertain; preconnect and ICE leave `webRequest` and CSP; a script could close the wrapper and forge its own result; a person's input between fast scripted inputs fell inside the grace; a run's end withdrew the `confirm()` its step opened, so the agent could never answer it; per-run partitions leaked one session each | A partition per run (leaks sessions); blocking WebRTC only in the script world (the proxy and IP policy hold below the page); running the compile check in the sandbox (a breakout already runs there); matching trusted events by timing only | Electron offers per-session network isolation without a proxy, or scripts need `Page.press` |
| D23 | The Mixdog browser code is an independent fork of 1.3.4 (`968ee089`), kept as plain modules in `src/` (R13); Mixdog is not tracked | Builds no longer fetch from the network or patch sources at build time, `src/` no longer imports `build/`, and the code is maintained where it runs; only the parts used here are kept | Fetching pinned originals and adapting them at build time behind exact-once guards (the design up to v0.3.1); following Mixdog releases | A Mixdog fix is needed here (port it by hand as a normal change) |
| D24 | A trusted `input` or `change` on a picker or dropdown control (single-row `select`, date-like and `color` inputs, `datalist` inputs) counts as page input; every dispatched command holds a value credit for the changes it causes | Chromium draws these choosers as separate popup widgets, so a person's choice there reaches the page as a value change with no `pointerdown` or `keydown`; the real-device check of AC15 let such choices through during automation | Blocking pickers during automation (page code calls `showPicker()`, which the isolated world cannot stop without patching the main world); counting every trusted `input` (`execCommand` and a script's `click()` on a checkbox make trusted events, so ordinary pages would pause) | Electron exposes input to popup widgets or a chooser API for `select`, date and color |
