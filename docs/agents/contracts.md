# Contracts

Owns: the binding behavior rules: authority and isolation, observation and input,
DevTools reads, script runner, human DevTools, handoff state machine, native requests
and permissions, result vocabulary. A change that breaks a rule is a defect even when
tests pass.
Not here: requirements C1–C10 and acceptance criteria (`requirements.md`), rationale
(`decisions.md`), code locations (`architecture.md`).
Update when: a rule, state, error code or result field changes, in the same change as
the code.

## Authority and isolation

- Two caller authorities, chosen by the registration through `WB_AUTHORITY` and never inferred: `hook` (default; the Mixdog plugin) and `connection` (a plain MCP stdio registration such as Claude Code's `claude mcp add`). An unknown value, or a missing or relative data root (`MIXDOG_PLUGIN_DATA` for `hook`, `WB_DATA_DIR` for `connection`), stops the server before it allocates a connection; neither authority falls back to the other.
- Hook authority: arguments carry `_channel` (this connection) and `_lease` (PreToolUse ticket). A hook failure denies that call and nothing else.
- Connection authority: arguments carry neither `_channel` nor `_lease`. The tool schema and the server instructions hold no value that differs between server processes, so a host may keep them for a whole session, across server restarts. The gateway addresses its own companion with its own channel and ignores a `_channel` argument (a host that kept an earlier schema still sends one). A restarted server is a new connection without tabs: earlier tab ids are refused `CLOSED_TAB`. The MCP connection is the only caller (`CONNECTION_CALLER`): one session, one profile and one caller generation per connection, ended only with the connection (stdin EOF, process exit, `revoke`). Right before each call the gateway takes that call's ticket from the companion over its own hook-role pipe connection, with a fresh call id, so every call passes `CallerAuthority.consume` under the ticket rule below. The schema has no `_lease`; a `_lease` argument is refused `not-executed` (`INVALID_ARGUMENT`) before anything is sent. No `endpoint.json` is written, so the pipe key stays in process memory. No hook events arrive: MCP cancellation aborts its own call, and turns start no generations. Separate host sessions are separate connections with separate companions; agents inside one session share its caller. The server instructions (`CONNECTION_INSTRUCTIONS`, at most 4096 characters) carry the skill's guidance.
- Ticket: single use, 10 s, bound to `sessionId`, `callId`, `toolName === BROWSER_TOOL` and the sha256 of the canonical arguments without `_lease`.
- Hook authority: `end` aborts the session's admitted work and blocks its late calls. `UserPromptSubmit` starts a new generation even when `end` was lost.
- Tabs of another session fail with `FOREIGN_TAB`. Profiles are per connection and session.
- Pipe `hello` must match the channel and the 43-character key (constant-time compare). One gateway per companion. Methods per role: gateway `status`, `call`, `shutdown`; hook `begin`, `end`, `issue`.
- `status` is answered by the gateway without consuming a ticket.

## Observation and input

Perception: `src/browser/perception/` (walker, model, refs, render), `src/browser/settle.mjs`, `src/browser/signals.mjs`; rationale D13–D19.

- Capture: one synchronous walker snapshot per frame in that frame's isolated world, all frames in parallel; the snapshot carries its own checkpoint (document, viewport, scroll). No all-frame quiet or revision is required. A subframe that fails or is hidden degrades to a line in its iframe entry; only a missing root fails (`ROOT_UNAVAILABLE`).
- Frame setup (`FrameDriver#rebuild`): only the root is required. A child whose session, frame tree, isolated world or walker cannot be set up is an unavailable frame (`iframe … unavailable`) and is set up again on the next observation; an iframe whose target initialization failed stays paused and never blocks the page. A frame without its own world is never evaluated (`FRAME_UNAVAILABLE`), so nothing falls back to the page main world.
- Bounds: at most 50 frames (`FRAME_CAP`, root first, then tree order) get a world and the walker; the rest are `hidden frames`. A model holds at most 30 000 items (`partial page`). The walk is iterative (no stack limit on DOM depth) and scans at most 12 000 elements per frame. Budget cuts are linear (mark, then filter).
- Never observed: password and OTP values, CSS or script text, `display:none` or `visibility:hidden` content, screen-reader-only text, unslotted shadow content. Accessible names use rendered text only: the name helper's (`semantics.mjs` `accessibleName`) label, `aria-labelledby` and content reads go through `renderedText` (an unrendered element contributes nothing, except an `aria-labelledby` target, whose text nodes outside `script`, `style`, `template` and `noscript` count as ARIA requires). A control whose computed name is empty (an image-only link or button) is named by the text alternatives of its rendered embedded content in tree order (walker `embeddedName`): `aria-labelledby`, `aria-label`, an `img` `alt`, an `svg`'s own `title`, then `title`; nested controls, form fields, editable content and `aria-hidden`, `display:none`, `visibility:hidden` or `opacity:0` descendants never contribute. Sensitive fields print `sensitive` and never match `find`.
- Sensitive fields (walker `isSensitive`, sticky per document in a `WeakSet`, so a show-password toggle keeps it): `input`, `textarea`, `select` and contenteditable elements that are `type=password`; have `autocomplete` `one-time-code`, `cc-*`, `current-password` or `new-password`; match by name, id, `aria-label`, `placeholder` or label text a multilingual list (pass, pwd, secret, token, otp, one-time, cvv, cvc, csc, security code, card number, ssn, pin, auth number/code, sms code, verify code, `code`, 인증번호, 보안코드, 주민(등록)번호, 비밀번호, 암호, 승인번호); are `inputmode=numeric` with `maxlength` ≤ 8, or one-digit boxes in a group of four or more; or use `-webkit-text-security`. Fields the person typed into during a handoff become sensitive for the rest of that document (`privatize` at return, before the first agent observation). `read` asks the walker at read time, not the last model.
- Page code beside secrets: `evaluate` (either world) and `console` with `expression` return `not-executed` `SENSITIVE_PRESENT` while any document page code can reach holds a non-empty sensitive or privately typed field: every frame of the page, and of the profile's other windows, with the target frame's origin (`contentDocument`, `opener`, `open('', name)`); a same-origin frame that cannot be checked (no walker world, beyond `FRAME_CAP`) counts as holding one. They are also refused while any window of the profile is not in `automation` (a named popup under the person's control). This holds for direct calls and for script steps. The person finishes signing in (submits) before returning control; the agent may clear a field with `fill` and `text:""`.
- Text matching and reads never reveal a sensitive field's own text: `read` of a container and `observe` `wait.text`/`wait.gone` (`maskedText`) replace the text of every sensitive element in the subtree (a contenteditable secret is part of `innerText`), and a container read that held one also prints `sensitive (value withheld)`.
- Refs `e<n>`: unique per connection, never recycled, never fall back to another node. A ref stays valid while its node is connected in the same document with the same role, accessible name and presentation `generation`; unrelated updates, scrolling and state changes keep it. Removal (a reinserted element gets a new ref), rename, document replacement, or a new `generation` retires it (`STALE_REF`). `generation` increases on handoff and fail-closed drains, on return, and on hide; not on Stop or show. A ref of a closed tab is `STALE_REF`. Cap 50 000 entries, indexed per tab and frame; retired entries are evicted first, then only the inserting tab's own oldest refs.
- Tabs are `t<n>`; frames are named by their iframe ref (`frame`), never by CDP ids.
- Input pipeline (`#validate` → `#perform` → settle → `#present`):
  1. Paint holding first (`FrameDriver.inputReady`), so the checks below are the last reads before dispatch: before the first input to a document, wait until every local root on the target's frame chain (the root and each out-of-process frame) has a first contentful paint (`getEntriesByType('paint')`, which page script cannot spoof), else 700 ms after `responseStart`. Chromium acknowledges, then drops, input during paint holding.
  2. Validate, read-only: owner, live ref, same document, role and name (`describe`), visibility, enabled, stable rect, hit test at the dispatch point, each ancestor frame owner holding still across two animation frames inside its parent document (`NOT_ACTIONABLE` "Target frame kept moving"), and hit tests of those owners (`FRAME_OCCLUDED`, `UNSUPPORTED_FRAME_GEOMETRY`). Whether the target is in view is checked live; an out-of-view target is scrolled into view (`preparation=scrolled`); nothing else mutates. A custom checkbox, radio or file input hidden behind its label (opacity 0, a tiny box, `display:none`) is emitted with its label's box, and pointer input aims at the label.
  3. Dispatch once. Input admission (`#owned` with input): owner match, not paused, visible, connected, no dialog cleanup pending, `presentation.assertAutomation(generation)`. The admission check and `markSent` run inside the guarded command, right before it is sent, so a Stop in between leaves nothing sent and nothing to release. A one-shot capture guard in the target's walker world checks that the trusted `pointerdown` (keys: `keydown`, text: `beforeinput`) lands on the validated element: a press that lands elsewhere is released far outside the viewport so no click forms, and a key or text aimed elsewhere is cancelled in the same turn and nothing after it is sent; the result is `executed` with `code=TARGET_MISMATCH`. For keys and text every other frame of the page with a walker world is armed for the same dispatch, and a stray `keydown` or `beforeinput` there is cancelled the same way (focus can move between frames). Keys and text check before each step, never after the last, that the target is the live, enabled, focused element of its document and that its document has focus (`hasFocus()`; `activeElement` stays set in a frame that lost focus): Tab, Enter or Escape may move focus, navigate or close a widget, and that is their effect.
  4. Settle (bounded, never sends input): 150 ms navigation probe; a started navigation waits up to 3 s for DOMContentLoaded of the new document; then a 100 ms quiet window of structural mutations in the root and target frames, capped at 1 s (500 ms for `scroll` and `evaluate`) by a host timer, whatever the page does. Requests the action started are polled; a JS dialog or a popup ends settle at once; abort rejects. Text-only mutations do not delay settle.
  5. Observe; one read-only retake if the capture fails.
- Disposition: failure before dispatch → `not-executed` with `requestedInputDispatched:false` and `preparation`. Failure during dispatch (`markSent` reached, no acknowledgement) → `uncertain`, `replaySafe:false`; a JS dialog that opens before acknowledgement is `uncertain` with `operationPending` (it blocks the renderer, so the acknowledgement cannot arrive); any other native request (file chooser, permission) gives the input 300 ms (`NATIVE_REQUEST_ACK_GRACE_MS`) to be acknowledged or finish before the same decision. Acknowledged dispatch whose observation fails twice → `executed` with `observed:false`, `cause` and `replaySafe:false`, never `uncertain`. An acknowledged page-script error is `executed` with a `code`. A cancelled action reports why: `AUTOMATION_PAUSED` (with the pause reason), `CLOSED_TAB`, `RENDERER_GONE`, `CONNECTION_CLOSED`, `TIMEOUT` or `ABORTED`. Nothing retries or resends input.
- Delivery: once the caller has a result (a parked dialog, a timeout), the lane may still finish, but it never moves the agent's diff base or drains signals. `#present` does everything that can fail first, then commits the view and drains.
- Results after an action (`snapshot`, default `diff`): changes since the agent's last view of the tab. Additions are everything a default view prints now that the agent was not shown: new content, content that scrolled in, was uncovered or was cut by a budget before, live regions (`alert`, `status`, `log`, `marquee`, `aria-live`), short fixed-position toast text and plain text, offscreen live content included. A diff larger than 60% of the view is replaced by a full default snapshot. A scroll since the last view prints the `view` line.
- Screenshots only on request (`screenshot:true`), at CSS scale (image pixels = CSS pixels). A point acts only against the tab's latest screenshot-bearing snapshot, the same `generation`, document, viewport and scroll, and an unchanged 24×24 CSS-pixel tile around the point (`STALE_COORDINATES`, `POINTS_UNAVAILABLE`). The point is then hit-tested from the root through every frame: a hit chain with effective opacity below 0.1 or an element failing `checkVisibility({opacityProperty:true})` is refused `POINT_HIDDEN_TARGET`, naming the hit element, a hit iframe's host and the frame it is in; a chain that cannot be followed is `POINT_UNVERIFIED`.
- Focus: windows open with `showInactive()` and never take focus on agent-initiated opens, actions or `handoff`. `Emulation.setFocusEmulationEnabled` is on in `automation` and off in `native-handoff`, on the page and on every out-of-process iframe session, so the page behaves as focused without OS focus. This is separate from the DevTools rule that recording never emulates.
- Escape paths around the shield (native pickers, dropdown windows): the walker world listens for trusted `pointerdown` and `keydown`, and for trusted `input` and `change` on controls whose choice is made in a separate browser picker or dropdown window and reaches the page with neither (a single-row `select`; a `date`, `datetime-local`, `month`, `week`, `time` or `color` input; an input with a `datalist`), and reports them through a binding that exists only in that world (`Runtime.addBinding` with `executionContextName`). Each dispatched press (`mousePressed`) or key (`rawKeyDown`, or `keyDown` for a key with a character) takes one credit that exactly one trusted event of its kind may claim, until 500 ms after its command returned (`INPUT_CREDIT_MS`); every dispatched command also takes a value credit that covers all the value changes it causes over the same span. Any other trusted `pointerdown`, `keydown` or picker value change, including one between fast scripted inputs, fails closed with `unexpected-page-input`; a picker value has already changed when it does. The `select` action's events are untrusted and never count. Controls inside closed shadow roots are not covered.
- Signals (`SignalQueue`, per caller session): only `state` and `closed` signals leave a tab that is not in `automation`. A download started outside `automation` is private for its whole life: never listed in `downloads`, never signalled, including when it ends. A tab's queued page-content signals are purged when a handoff or fail-closed drain begins. Script steps drain nothing; the run's final views do. A session's queue is dropped when the caller session ends.
- URLs in the header, `navigated`, `popup` and `loading` signals and link hrefs go through `redactURL` (user info, sensitive query and fragment parameters such as `code`, `state`, tokens).

Text grammar (`render.mjs`; status line and MCP envelope in `src/mcp/tool.mjs` `statusLine`, `toolResult`):

| Line | Form |
| --- | --- |
| Status (first) | `<disposition> <action>[ <ref>] tab=<t>[ snap=<s>][ code=<C>][ observed=false cause=<C>][ dispatched=false][ preparation=<p>][ replaySafe=false]` |
| Signal | `signal[ <t>] <event>` (navigated, popup, download, dialog, state, loading, pending requests, console/network counts since the last result), drained once per session, current tab first; `signal tab <t> closed` |
| Header | `page "<title>" <url>` then `view <w>x<h> scroll <y>/<height>[ points]`, on first view, URL change or screenshot; the `view` line alone after a scroll |
| Element | `[indent][e<n> ]<role>[ "<name>"][ <states>][ ="<value>"][ <href>]`; `text "…"`, `h<n> "…"`, `iframe <host>[ unavailable][ covered]` |
| Summary | `+N offscreen (A above, B below): …`, `+N covered`, `outline: …`, `+N deeper (raise depth or scope)`, `hidden frames N: <hosts>`, `partial page: element scan capped`, `+N more lines (over budget; use find or scope)` |
| Diff | `diff <from>→<to> +A ~C -R`, then `~ <line>`, `+ <line>[ in e<n>]`, `- e<n> …`, `- e<n> … (hidden)`, `+N new offscreen`, `+N more changes (observe for the full view)`; or `no change since <s>` |
| Find | `find "<q>": N match(es)` then lines with `in e<n> <role> "<name>"` ancestry; when some elements match every term, only those are listed. Words only: a `/…/` query and a whitespace-only query are refused (`INVALID_ARGUMENT`), so no agent pattern is compiled in the host process |
| Text (`mode:text`, `read` without a ref) | one item per line, every page string a quoted literal after a fixed marker (`text "…"`, `h<n> "…"`, `<role> "<name>"`, `<role> ="<value>"`, `iframe "<host>"`), so page text cannot forge a status, signal or ref line |

`quote` escapes JSON specials plus U+2028, U+2029, U+0085 and bidi controls (U+202A–202E, U+2066–2069). Roles and states outside the walker vocabulary print as `generic`.

Budgets are estimated tokens everywhere (ASCII/3.7 + 1.1 per non-ASCII character): default 6000, full 30 000, scope 12 000, text 12 000. Whole lines are dropped, never part of one; in snapshots the lowest priority goes first (subframe text, root text, subframe elements, root elements), in `mode:text` the tail goes.
- `evaluate` is a mutation. Default `world:'isolated'`: its own isolated world, DOM only, no page globals. `world:'page'` is an explicit opt-in to the frame's page main world: page scripts can observe, spoof or tamper with the evaluation and its result (D11). Neither world has Node or host bindings.
- `read` returns rendered text (`innerText`), never `textContent`, and never a sensitive value (`sensitive (value withheld)`), as the walker judges it at read time.
- Agent URLs: credential-free http(s) only (`pageURL`). Address bar: `addressURL` (bare host → https, loopback → http).
- `FenceQueue`: cancellation settles the caller at once; the lane stays fenced until the actual operation settles.

## DevTools reads

Actions `console`, `network`, `inspect`, `performance` (`src/browser/devtools.mjs`; rationale D11, exclusions D12).

- Gates: tab ownership and `presentation.assertObservable()`, the same as `observe` and `read`; otherwise `FOREIGN_TAB` or `PRIVATE_HANDOFF`. Reads that waited on the browser re-check ownership, observability and `generation` before answering.
- Never an observation or PNG, never a new `snapshotId`, never a ref change, never `uncertain`. Results are compact JSON rows.
- Dialog first: while a page JS dialog is pending, `console` with `expression`, response bodies (`network` with `body:true`) and `performance` return `not-executed` with `DIALOG_OPEN` and the pending requests instead of stalling behind the modal.
- `console` with `expression` that exceeds its 2 s timeout is terminated by V8 and fails `SCRIPT_TIMEOUT`; the page stays usable. Each read and `inspect` call uses its own object group, released when it ends.
- Signals: action and observe results carry `signal console N errors` and `signal network N failed` counts since the tab's last result (`DevToolsRecorder.since(cursor)`); the rows stay behind `console` and `network`.
- `in` (iframe or worker) marks rows from out-of-process sessions and, for same-process iframes, rows whose execution context or `frameId` belongs to a child frame.
- Lane: `console` and `network` (list, detail, body) and `performance` run beside the per-tab action lane and answer while an action is in flight. `inspect` runs in the lane like `read`.
- `console` with `expression` also runs beside the lane. It runs page code, so it is refused with `AUTOMATION_PAUSED` while the tab is paused for any reason (explicit Stop included), and returns `not-executed` while a page dialog is pending.
- Privacy, per page: only `presentation.mode === 'automation'` records. Entries produced in `draining`, `native-handoff` or `returning` are dropped at arrival and by timestamp (`PrivacyWindows`), counted only as `withheld`. Requests in flight when recording stops end as `incomplete`. A chain frozen as `incomplete` or withheld keeps every later event and redirect hop private.
- Privacy, per profile: service and shared worker sessions serve every page of the owner's profile. Their events are dropped, and their in-flight requests freeze, while any page of the profile is not in `automation` (profile-level `PrivacyWindows`). Page, iframe and dedicated worker sessions follow their own page only.
- Window bounds: a window's end is never before its start, and a clock step while private widens it. Over 32 windows, the oldest two merge, which can only drop more.
- Replays: `Runtime.enable` and `Log.enable` replay stored entries on a session whose target ran before the attach, or on a re-attached main session. Per session, the cutoff is set before those enables, so replayed entries are dropped.
- Return flush: before `finishReturn`, `#resume` makes one CDP round trip (`devtoolsFlush`) on every recording session of every page in the profile. Events queued during the handoff therefore arrive while recording is still off.
- Worlds: console calls and exceptions are recorded only from page main worlds (default execution contexts) and workers. Output of the agent's isolated worlds (`evaluate`, observation) is not recorded.
- Redaction (best effort, by name and shape):
  - Header values are replaced when the header name is `Cookie`, `Set-Cookie`, `Authorization`, `Proxy-Authorization` or `DPoP`, or contains token/secret/api-key/session/auth/csrf/password/credential/signature/ticket/jwt/assertion/saml, or ends in `key`.
  - `Location`, `Content-Location` and `Referer` (also relative values), `Link` and `Refresh` URLs go through URL redaction. Other header values go through the text rules.
  - URLs (rows, details, stack locations, URLs inside text): user info, then query and fragment parameters by sensitive name. Names include pass/pwd/secret/token/auth/session/otp/cvv/card number/credential/api-key/access-key/private-key/signature/ssn/jwt/assertion/saml/ticket and the exact or separated names `code`, `state`, `sig`, `key`, `nonce`. Values shaped like a JWT or a `Bearer`/`Basic` credential are also redacted.
  - Text (console messages, exceptions, log entries, header values, unparsed bodies): URLs inside the text, `Bearer`/`Basic`/`Digest`/`Negotiate` credentials, JWT-shaped values and `name: value` / `name=value` pairs with a sensitive name.
  - Request and response bodies: JSON keys (parsed up to 1 MiB, with text rules on string values), form fields, multipart parts, then the text rules on the rest.
  - Not redacted: secrets under unrecognized names or without a recognizable shape, HTML and other markup content, binary bodies (size and type only), `inspect` output, and results of `console` with `expression` and `evaluate`.
  - No cookie or storage CDP API is called.
- Bounded text work: every pattern runs on page text cut to at most twice its output cap and is linear (no nested quantifiers, scans start at token boundaries). A 64 KiB adversarial input redacts in milliseconds.
- Enabled domains must not change page behavior: `Network` (buffers below), `Log`, `Performance`, `Runtime` on workers, `CSS` lazily on first `inspect`. Never cache disabling, interception, pausing, emulation or `Debugger`. `Runtime.discardConsoleEntries` runs every 200 console events per session.
- Recording start:
  - Page and iframe sessions start recording before the target runs (load-time entries).
  - Worker, service worker and shared worker sessions start after their startup release; `Runtime.enable` replays their earlier console output, while their earliest requests may be missed.
  - Recording is best effort: commands are bounded, and recording never fails, fences or delays target setup.
- `console` with `expression`: `Runtime.evaluate` in the page main world with `throwOnSideEffect:true` and a 2 s `timeout`; a detected side effect fails `SIDE_EFFECT`. `throwOnSideEffect` is V8's best-effort check, not a security boundary. Page-defined functions, overridden built-ins and getters that V8 accepts still run, so the result is reported by the page and may be faked. Objects return V8 previews.
- `inspect` takes a live ref (validated like `read`) or `target.selector` (+`target.frame`, an iframe ref) resolved in the frame's isolated world; it never observes.
- Bounds (`DEVTOOLS_LIMITS`):
  - Rings: console 500, network 1000.
  - Rows: default 30, max 100. Characters: default 8192, max 65536.
  - Field caps: message 300, row URL 200 (stored 2000), header value 256 and 2048 per side, stored request body 2048.
  - `Network.enable` per page: main session 6 MiB, each other session 1 MiB, page total 10 MiB, then 0. Per resource 1 MiB, post data 64 KiB.
  - Privacy: 32 private windows (merged), 5000 frozen request keys.
  - Inspect: 2000 stylesheet headers, 8 rules of 200 characters, 20 listener types.

## Script runner

Action `run` (`src/browser/runner/`; rationale D20): `{script, tabId?, timeoutMs?}` runs a short Playwright-like script in one call.

- Sandbox (`sandbox.mjs`): one hidden `BrowserWindow` per run with `sandbox`, `contextIsolation`, no Node in any frame or worker, the shared in-memory runner partition (`wb-runner`, set up once, storage and cache cleared after every run), a strict CSP, every request cancelled except its `data:` bootstrap, and navigation, popups, permissions, downloads, dialogs, webviews and DevTools denied. Connections outside request interception go nowhere: the partition uses a dead fixed proxy (`http://127.0.0.1:9`, loopback not bypassed) for preconnects, WebRTC is limited to proxied UDP (`disable_non_proxied_udp`) and the run wrapper deletes the WebRTC constructors before the script runs, and the bootstrap turns DNS prefetch off for good (`x-dns-prefetch-control: off`). Its only exit is `window.__wbBridge.call(op, args)` from the preload (`app/runner-preload.cjs`), which carries a per-run 32-byte nonce the main world never sees. `routeOp` accepts only that run's own sandbox main frame, on its bootstrap URL, with the nonce (constant-time compare). The sandbox is destroyed when the run ends (its renderer crashed unless another live run shares that process, then the window destroyed), which also ends a CPU-bound script. Node `vm`, the page world and `utilityProcess` are not used to run scripts.
- Compile check (`syntaxError`, main, nothing runs): the script must parse as one async function body on its own (the dynamic-function parser, so a script that closes the wrapper and continues outside it fails) and the whole program must compile (`vm.Script`); otherwise the run ends `syntax` (`SCRIPT_SYNTAX`) before any sandbox exists.
- Bridge (`bridge.mjs`): an op allowlist (`open`, `navigate`, `click`, `fill`, `type`, `press`, `select`, `upload`, `scroll`, `evaluate`, `dialog`, `read`, `find`, `snapshot`, `wait`, `tabs`, `close`) with strict argument shapes; no `run`, `handoff`, `respond`, `revoke`, points or page-world evaluate. `validateOp` then runs the host's own `validateArgs` on the arguments it built, so whatever the host would refuse is refused before anything runs (`INVALID_RUNNER_OP`, catchable, never sealing); `BrowserHost.execute` tags its own argument refusals `requestedInputDispatched:false`. Each op is one `BrowserHost.execute` call under the run's caller (same session, through every gate and the pipeline above); input ops render no snapshot. The run caller's `assertLive` runs before every op and right before every dispatch: it refuses once the run has ended, and when any tab of the run is stopped, paused or under the person's control (a synchronous host check), and the run then ends at once (`RunnerBridge.end` aborts it, so ops in flight are refused before they dispatch).
- Native requests a step opens (JS dialogs, file choosers, permission prompts) belong to the run's own caller, not to the step: they outlive the run, and the agent answers them with `handle_dialog` or `respond` after the run's result.
- Floods: at most 2000 ops per run, refused ones included (then the run ends `limit`, `RUN_LIMIT`), and 4 in flight at once (`RUN_BUSY`, catchable). `open` is refused at 32 open tabs per session (`TAB_LIMIT`, direct calls too). A tab joins the run (final view, interruption check) only once the host accepted it as the caller's own.
- Outcomes: `not-executed` throws a catchable `RunnerError` (nothing was sent, so continuing can never resend input). `executed` with a code throws a catchable error and counts as executed, also when its observation could not follow (`observed:false`, `operationPending`). An accepted `close` or `dialog` answer counts as executed. `uncertain` seals the bridge: every later op is refused, even when the script catches, and the run ends. Stop, handoff and other pauses (the host's pause reason), caller end, cancellation and the deadline end the run. Auto-wait retries only `TARGET_NOT_FOUND` and `NOT_ACTIONABLE`, within the op timeout (default 5 s, max 10 s, the host's `wait` bound) and the deadline; nothing else retries.
- Deadline: default 60 s, 1–100 s, inside the 120 s gateway call limit; an op still in flight after the end gets 3 s to settle and is then `unknown` (uncertain) if it was input.
- Report (text): status line (`executed`/`uncertain`/`not-executed`/`observed` `run`), then `run <status> N steps T ms[: message]`, one line per step for the first 60 (`<n> <outcome> <op> <target> [code=…] <ms>ms`, then `+N more steps`; typed text and files shown only as counts), `return <json>` up to 4000 characters (`…(+N)` says how much was cut), `console:` lines (300 characters each, 2000 together), and `-- <tab>` with each touched tab's final diff against the agent's last view (steps never move it). Final views: at most 4 tabs, 6000 characters each and 12 000 together, cut at line boundaries, all within one budget of `min(10 s, 115 s − elapsed)`; tabs over a cap or the budget print `-- <tab> not shown: observe <tab>`, and a tab parked behind a dialog prints the dialog. The whole report is cut at 24 000 characters. `replaySafe:false` when anything executed or is uncertain.
- Everything from the script's world is data: the wrapper captures the builtins it needs before the script runs, and main believes only a plain `{status, …}` object of strings, then clips and escapes every field (line breaks, C0/C1 controls, U+2028/2029 and bidi controls) like the console lines. A malformed answer is `error` with the steps and `replaySafe` kept.
- The lease digest covers the script like every argument (`src/shared/authority.mjs`), so a ticket never authorizes a different script.

## Human DevTools

- Native menu `Open DevTools (while you have control)` is enabled only in `native-handoff`; the host refuses it in every other mode. It opens the page view's DevTools in detached mode, never the toolbar's or shield's.
- DevTools close whenever the mode leaves `native-handoff`, including a fail-closed exit to `draining`, and when the page closes. A front end still loading (`devtoolsOpening`) is awaited, within a bound, before it closes.
- `#resume` closes DevTools after `beginReturn` and before the trusted return observation, then returns window focus to plugin chrome. That return is person-initiated, so it may focus; agent-initiated opens and actions never do.
- DevTools that open after a slow front-end load are closed by the `devtools-opened` handler whenever the mode is not `native-handoff`, however long the load took; the bounded wait in `#closeDevTools` never leaves them open.
- DevTools appearing in `automation` is closed and fails closed (`devtools-outside-handoff`). Appearing in `draining` or `returning`, it is only closed.
- The agent's own CDP session stays attached while DevTools opens and closes (Chromium multi-client).

## Handoff state machine

Two gates per page: `p.paused` (null or a reason) blocks input; `presentation.mode`
blocks observation with `PRIVATE_HANDOFF` unless it is `automation` (or `returning`
for the trusted return check). Every transition increments `generation`.

| From | Event | To |
| --- | --- | --- |
| automation | person clicks or types on the shield; toolbar Take control; menu Human handoff; `handoff` action | draining, paused = reason |
| any | fail-closed trigger | draining, paused = trigger |
| draining | lane idle, held keys and buttons released, CDP native mode on | native-handoff: shield hidden; page focused when the person started it, window only flashes (`flashFrame`) for an agent `handoff` |
| native-handoff, draining, or paused automation | toolbar Return or Resume; menu Resume automation | returning |
| returning | fresh trusted observation passes | automation, paused = null |
| returning | observation fails | draining, paused = `return-failed` |

- Resume comes only from that window's toolbar document or native menu; no tool action resumes. Resume is refused while a page dialog is pending.
- Stop (`explicit-stop`) blocks input without changing mode, survives hide, show and handoff, and clears only on Resume.
- The gesture that starts a handoff is never delivered. A wheel cannot confirm a handoff; an explicit control is required.
- Fail-closed triggers: `unexpected-page-input`, `page-not-shielded`, `presentation-hidden`, `presentation-minimized` (automation only), `presentation-navigation-blocked`, `presentation-renderer-lost`, `presentation-lost`, `devtools-outside-handoff`.
- Other pause reasons: `human-handoff`, `shell-pointer-intervention`, `shell-keyboard-intervention`, `inherited-native-handoff`, `return-failed`, `permission-revocation`.
- Toolbar messages count only from the window's own toolbar frame and URL; the main process enforces every mode rule.
- Chrome documents never navigate, open windows or attach webviews; an attempt fails closed.
- Pages keep painting while occluded (`CalculateNativeWinOcclusion` disabled before app ready). `FrameDriver.presented()` is bounded (3 s) and fails as `CAPTURE_FAILED`, never a hang.

## Native requests and permissions

- One interface: `requests` lists; `respond` takes `requestRef` and exactly one of `optionRef`, `files` or `cancel:true` (`text` only for a prompt option). Refs are handles, not approvals.
- Kinds: `javascript-dialog` (alert, confirm), `file-picker` (HTML file input), `hid`, `usb`, `notifications`, `geolocation`.
- Requests are withdrawn, not denied, on Stop, handoff, return start, hide, disconnect, navigation, caller end, document change and expiry (120 s). A script step's requests belong to the run's own caller, so the end of the run does not withdraw them.
- `upload` files and `respond` files: local drive-letter paths only, resolved to their real path (`fs.realpath`), which must be a regular file and is what the page receives; a network or device path (`\\host\share`, `\\?\…`, `//host`) is refused before any filesystem call, which could otherwise send the user's NTLM credentials to that host.
- A human deny or cancel is terminal for that scope within the connection.
- Policy `browser-policy.json`, loaded once per connection, never from MCP arguments:
  - `disabled`, or missing or malformed: no new grants.
  - `manual`: OS consent through `native-consent.exe`.
  - `delegated`: `permissions` ⊆ {hid, usb, notifications, geolocation}, `origins: owned-pages`, `selection: offered-option`, `lifetime: caller-generation`, `newGrants: true`. The live authenticated owner picks an offered option through `respond`.
  - Shipped default: `delegated` with all four kinds.
- `revoke` closes every window of the connection by terminating the companion; only the gateway confirms the exit.
- Unsupported, refused with a reason: Bluetooth, serial, display capture, File System Access pickers, `window.prompt` (Electron 44.9.1).

## Result vocabulary

- `disposition`: `observed`, `executed`, `uncertain` (with `replaySafe:false`), `not-executed`, `connection-terminated`.
- Text actions (all except `JSON_ACTIONS` in `src/mcp/tool.mjs`): status line plus body text, and an image block only with `screenshot:true`. JSON actions: `status`, `list_tabs`, `requests`, `respond`, `permissions`, `downloads`, `revoke`, `console`, `network`, `inspect`, `performance`.
- `isError`: true for `not-executed`, `uncertain`, `failed` and `failed-or-unknown`, and for a text result carrying a `code` (page-script error, failed navigation, `WAIT_TIMEOUT`). `executed` with `observed:false` is not an error.
- Errors: `BrowserHostError(code)` from `contract.fail()`. Text actions answer `failed <action> … code=<C>` (or `not-executed … dispatched=false`) plus `reason …` and candidates. JSON actions answer `{disposition, code, reason, replaySafe:false}` with disposition `failed-or-unknown` or `not-executed`. Code inventory: `grep "fail('" src` (not mirrored here).
- Runtime capability report: `BrowserHost.status().capabilities`.
